# 釐清問題

未登入的使用者嘗試建立旅程時，是否應操作失敗？

# 定位

Feature：建立旅程 — 目前所有 Example 的 Given 步驟皆為「使用者已登入」，但沒有任何 Rule / Example 驗證「未登入」情境下的行為。
對照 `spec/features/加入旅程.feature` 已有明確規則「使用者必須已登入才能加入旅程」，`建立旅程.feature` 缺少對應的前置條件規則，造成 feature 間覆蓋度不一致。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 未登入使用者操作失敗，比照 `加入旅程.feature` 新增對應 Rule + Example |
| B | 未登入使用者會被路由層導向登入頁，不視為「操作失敗」，此規則不需寫入本 feature |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/建立旅程.feature`：可能需新增 Rule「使用者必須已登入才能建立旅程」及對應 Example
- 前端路由保護（middleware / server action 授權檢查）

# 優先級

High
- High：登入狀態檢查為核心授權路徑，且與同類 feature（加入旅程）的覆蓋度不一致，影響測試設計完整性

---
# 解決記錄

- **回答**：B - 未登入使用者會被路由層導向登入頁，不視為「操作失敗」，此規則不需寫入本 feature
- **更新的規格檔**：無（不屬於此 feature 的業務規則範疇，維持現況）
- **變更內容**：不新增 Rule，`建立旅程.feature` 維持原狀；未登入的處理留給前端路由保護機制
