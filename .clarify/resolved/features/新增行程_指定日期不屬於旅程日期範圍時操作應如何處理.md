# 釐清問題

新增行程時，若指定的日期不屬於該旅程既有的旅程日期（例如超出旅程起訖日範圍），操作應如何處理？

# 定位

ERM：`days`（依旅程起訖日自動產生，`activities.day_id > days.id`）。
Feature：新增行程 — 目前所有 Example 使用的日期皆為旅程既有範圍內的日期，未涵蓋日期超出旅程起訖日、或不存在對應 `days` 記錄的情境。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 操作失敗，視為前置條件不成立（比照「使用者必須是旅程成員」的錯誤處理方式） |
| B | 系統不需後端額外檢查，因前端 UI 僅允許選擇旅程既有日期，不會出現此情境 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/新增行程.feature`：可能需新增 Rule + Example 作為前置條件之一

# 優先級

Medium
- Medium：屬邊界條件與錯誤處理完整性，不影響 happy path 核心設計，但影響測試完整性

---
# 解決記錄

- **回答**：B - 系統不需後端額外檢查，因前端 UI 僅允許選擇旅程既有日期，不會出現此情境
- **更新的規格檔**：無（此情境非系統驗證行為，不構成可測試的業務規則，依「無腦補或任意假設原則」不新增 Rule/Example）
- **變更內容**：無規格變更；記錄於此以避免未來重複提問
