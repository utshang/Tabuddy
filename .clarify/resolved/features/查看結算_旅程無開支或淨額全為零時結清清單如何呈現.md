# 釐清問題

旅程尚無任何開支,或所有團員淨額恰好為 0(互相抵銷)時,結算畫面與結清清單應如何呈現?

# 定位

Feature:`查看結算.feature` Rule「系統以最少轉帳筆數計算結清清單」——現有 Example 僅涵蓋有淨額差的情境,缺少空帳本與全數歸零的邊界 Example。MVP 功能清單另要求「有完整 loading / empty / error 狀態的精緻 UI」,empty 狀態的規格目前缺失。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 結清清單為空清單(0 筆轉帳),UI 顯示「無需結算」類 empty 狀態;無開支與全歸零兩情境行為一致 |
| B | 無開支時顯示「尚無開支」empty 狀態,有開支但全歸零時顯示「已互相抵銷」——兩情境區分呈現 |
| C | 隱藏結清清單區塊,僅顯示餘額 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- `查看結算.feature`:需補「無開支」與「淨額全為 0」的邊界 Example(演算法輸出為空清單)
- `src/lib/settlement` 單元測試:空輸入與全零輸入的邊界案例
- UI empty 狀態設計(spec.md 設計規範之 empty 狀態要求)

# 優先級

Medium
- 影響邊界條件與測試完整性,不阻礙核心演算法定義

---
# 解決記錄

- **回答**:A - 結清清單為空清單(0 筆轉帳),UI 顯示「無需結算」類 empty 狀態;無開支與淨額全歸零兩情境行為一致
- **更新的規格檔**:spec/features/查看結算.feature
- **變更內容**:新增 Rule「無任何開支或所有團員淨額為 0 時,結清清單為空」,含兩個 Example:「旅程無任何開支時結清清單為空」與「所有團員淨額互相抵銷時結清清單為空」(兩筆互抵的 custom 開支)。UI「無需結算」empty 狀態文案屬設計規範層,不寫入 feature。
