# 釐清問題

當一天有 3 筆以上行程，且使用者將某行程拖曳跨越多個位置時（例如把 order 4 的行程移到 order 1），介於原位置與目標位置之間的其他行程，順序應如何整體位移？

# 定位

Feature：`調整行程順序.feature` 的 Rule「成員拖曳後行程順序更新」目前僅有一個 2 筆行程互換位置的 Example（order2 移到 order1），未驗證 3 筆以上行程、且移動跨越多個位置時的位移邏輯。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 標準陣列搬移語意：移出原位置後，原位置與目標位置之間的其他行程依移動方向整體位移 1 個順位（例如 4→1：原 order1,2,3 各 +1 變成 order2,3,4） |
| B | 其他自訂位移邏輯 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/調整行程順序.feature`：需新增 3 筆以上行程、跨多位置拖曳的 Example，明確驗證中間行程的位移結果
- `spec/erm.dbml`：確認 `activities.order` 的跨屬性不變條件（保持 1..N 連續不重複）在此情境下仍然成立

# 優先級

Medium
- 影響測試完整性與邊界案例驗證；核心演算法方向已有既有 Example 提示（標準陣列搬移），但缺乏多筆行程的驗證用例，可能導致實作時對「中間行程」的處理出現遺漏。

---
# 解決記錄

- **回答**：A - 標準陣列搬移語意：移出原位置後，原位置與目標位置之間的其他行程依移動方向整體位移 1 個順位
- **更新的規格檔**：`spec/features/調整行程順序.feature`
- **變更內容**：在「成員拖曳後行程順序更新」規則下新增「拖曳跨越多個位置時中間行程依序位移」Example（4 筆行程，將 order4 移到 order1，驗證 order1-3 依序 +1）
