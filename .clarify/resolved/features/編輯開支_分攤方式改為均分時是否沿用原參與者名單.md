# 釐清問題

編輯開支將分攤方式由 custom 改為 even（或由 even 改為 custom）而未重新指定參與者時，是否沿用原有參與者名單？

# 定位

- Feature：`編輯開支.feature` Rule「成員可以編輯分攤方式與參與者，參與分攤的團員至少一人」——僅有「參與者為空時失敗」的 Example，缺少分攤方式切換的成功案例，也未定義切換時參與者名單的預設行為
- ERM：`expense_splits`（參與者名單即分攤明細的 user 集合）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 沿用原參與者名單：custom → even 時對原名單均分重算；even → custom 時需為原名單成員指定金額 |
| B | 切換分攤方式時必須重新指定參與者，未指定則操作失敗 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- `編輯開支.feature` 需補分攤方式切換的成功 Example（含 custom → even 的均分重算結果）
- 編輯開支表單的預設值行為（切換 split_type 時參與者勾選狀態是否保留）
- 與 [編輯開支_自訂分攤下僅修改金額時分攤明細如何處理] 為相關聯的分攤編輯行為，建議一併釐清

# 優先級

Medium
- 影響邊界案例與表單 UX，核心不變條件（總和相等、至少一人）不受影響

---
# 解決記錄

- **回答**：A - 沿用原參與者名單：custom → even 時對原名單均分重算；even → custom 時需為原名單成員指定金額（總和須等於開支金額）
- **更新的規格檔**：spec/features/編輯開支.feature
- **變更內容**：新增 Rule「編輯分攤方式而未重新指定參與者時沿用原參與者名單」與 Example「分攤方式由自訂金額改為均分時沿用原名單均分重算」（custom Alice 1000 / Bob 2000 → even 各 1500）
