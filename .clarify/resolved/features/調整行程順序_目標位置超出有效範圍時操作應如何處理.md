# 釐清問題

當使用者指定的目標 order 超出當日行程數量的有效範圍（例如小於 1，或大於當日行程總數）時，調整順序操作應如何處理？

# 定位

Feature：`調整行程順序.feature` 的 Rule「成員拖曳後行程順序更新」與其 Example 僅示範目標位置落在既有範圍內（2 筆行程中移動至 order 1）的情況，未涵蓋目標位置無效的情況。
ERM：`activities.order`（`spec/erm.dbml` 第 68 行）要求同一天行程順序為連續整數，若允許寫入超出範圍的 order 值，會破壞既有的「1..N 連續」跨屬性不變條件。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 操作失敗：目標 order 不在 1 至當日行程總數之間時，直接視為無效操作並失敗，順序維持不變 |
| B | 自動夾緊（clamp）：小於 1 視為移到最前面（order 1），大於總數視為移到最後面 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/調整行程順序.feature`：需新增「目標位置超出有效範圍」對應 Rule 與 Example
- `spec/erm.dbml`：`activities.order` 跨屬性不變條件是否需註明有效範圍的驗證規則

# 解決記錄

- **回答**：A - 操作失敗：目標 order 不在 1 至當日行程總數之間時，直接視為無效操作並失敗，順序維持不變
- **更新的規格檔**：`spec/features/調整行程順序.feature`
- **變更內容**：新增「目標順序超出有效範圍時操作失敗」規則，含「目標順序小於 1」與「目標順序大於行程總數」兩個 Example，驗證操作失敗且順序維持不變
