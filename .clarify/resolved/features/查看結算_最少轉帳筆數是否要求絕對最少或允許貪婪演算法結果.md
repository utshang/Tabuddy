# 釐清問題

「最少轉帳筆數」是要求數學上的絕對最少筆數,還是允許貪婪演算法(greedy)的結果?

# 定位

Feature:`查看結算.feature` Rule「系統以最少轉帳筆數計算結清清單」。

絕對最少筆數需要找出淨額和為 0 的子群組切分(子集合分割問題,NP-hard);常見的 greedy 作法(最大債權人配對最大債務人)保證至多 N−1 筆,但在存在「可獨立歸零的子群」時可能多出轉帳筆數。例:淨額 A:+500, B:−500, C:+300, D:−300,greedy 與最優解相同;但 A:+500, B:+500, C:−500, D:−500 之類情境需配對正確才達最少。CLAUDE.md 技術選型註明「圖論 / greedy」,與字面「最少」存在張力。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | greedy 即可——最大債權配最大債務,保證 ≤ N−1 筆;Rule 措辭改為可驗證的演算法定義 |
| B | 絕對最少——小團員數(MVP 情境)可用子集合切分窮舉/DP 求真最少筆數 |
| C | greedy + 零和子群優化——先找可獨立歸零的子群再各自 greedy,兼顧亮點與可行性 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- `src/lib/settlement` 演算法設計與複雜度(CLAUDE.md 定位為作品集核心亮點之一)
- Rule 措辭的可驗證性:「最少」若為 greedy 結果,規則應改寫為演算法保證(如「至多 N−1 筆」)
- 單元測試設計:能否對「最少」做屬性測試(property-based)取決於定義
- 依賴關係:本題答案決定〈存在多組最少筆數解時結清清單是否需有決定性順序〉的選項空間

# 解決記錄

- **回答**:A - greedy 即可(最大債權配最大債務,保證至多 N−1 筆;不要求 NP-hard 的絕對最少)
- **更新的規格檔**:spec/features/查看結算.feature
- **變更內容**:Rule 由「系統以最少轉帳筆數計算結清清單」改寫為可驗證的演算法定義「系統以貪婪配對計算結清清單(每輪由淨額最低者轉帳給淨額最高者),轉帳筆數至多為團員數 − 1」;Feature 描述同步改為「餘額與結清清單」。既有 Example 輸出即為 greedy 結果,不需修改。
