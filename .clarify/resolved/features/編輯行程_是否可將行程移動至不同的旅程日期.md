# 釐清問題

「編輯行程」是否允許使用者將行程移動到旅程中的另一個日期（即修改 `activities.day_id`），或者行程一旦建立後就固定屬於原本的旅程日期？

# 定位

ERM：`activities.day_id`（`spec/erm.dbml` 第 63 行），為必填的外鍵關聯至 `days`。
Feature：`編輯行程.feature` 目前的 Rule 與 Example 只涉及編輯 name，未提及能否改變所屬日期；`調整行程順序.feature` 的 Given/When 範例僅示範同一日期內行程的順序調整（拖曳改變 order），未涵蓋跨日期移動。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 可透過編輯行程將行程改到旅程內的任一其他日期，改動後兩個日期的行程順序（order）皆需重新編號 |
| B | 不可跨日期移動，行程一旦建立即固定屬於原本的旅程日期（MVP 不做此功能） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/編輯行程.feature`：是否需新增「編輯行程可變更所屬旅程日期」Rule 與 Example
- `spec/erm.dbml`：`activities` 與 `days` 的關聯說明是否需補充「day_id 可變更」的跨屬性條件
- `spec/features/調整行程順序.feature`：若允許跨日期移動，兩個日期的 order 重新編號規則需一併定義
- 若選 B，此議題屬於 MVP 範圍排除項，依 CLAUDE.md 範圍紀律不進一步實作

# 優先級

High
- High：屬於功能邊界的核心決策，影響是否需要額外的資料異動邏輯（跨表 order 重新編號）

---
# 解決記錄

- **回答**：B - 不可跨日期移動，行程一旦建立即固定屬於原本的旅程日期（MVP 不做此功能）
- **更新的規格檔**：`spec/erm.dbml`
- **變更內容**：`activities` 的 Table Note 補充「day_id 於建立後固定，編輯行程不支援變更所屬旅程日期（跨日期搬移為 MVP 範圍外）」
