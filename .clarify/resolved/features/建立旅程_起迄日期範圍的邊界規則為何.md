# 釐清問題

起日與迄日之間的先後關係邊界規則為何？（迄日是否可等於起日、或早於起日）

# 定位

ERM：`trips.start_date`、`trips.end_date` 目前僅標記為必填，未定義兩者的跨屬性先後關係約束。
Feature：建立旅程 — Rule「建立後系統依起迄日產生對應數量的旅程日期」目前只有 6 天（起迄不同天）的 Example，未涵蓋「起迄同一天（單日旅程）」與「迄日早於起日」兩種邊界情況。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 迄日必須晚於起日（不含當天），起迄同一天視為不合法，操作失敗 |
| B | 迄日必須大於或等於起日，允許起迄同一天作為單日旅程（產生 1 筆旅程日期），但迄日早於起日時操作失敗 |
| C | 系統不做此驗證，任何組合皆可建立 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/建立旅程.feature`：需新增 Rule + Example（單日旅程、迄日早於起日）
- `spec/erm.dbml`：可能需在 `trips` 的 Note 中補充跨屬性不變條件
- 旅程日期（days）產生邏輯需對應處理邊界情況

# 優先級

High
- High：直接影響旅程日期產生演算法的正確性與核心資料完整性，屬跨屬性不變條件

---
# 解決記錄

- **回答**：B - 迄日必須大於或等於起日，允許起迄同一天作為單日旅程（產生 1 筆旅程日期），但迄日早於起日時操作失敗
- **更新的規格檔**：`spec/features/建立旅程.feature`、`spec/erm.dbml`
- **變更內容**：
  - `建立旅程.feature` 新增 Rule「迄日不得早於起日」及對應 Example（迄日早於起日操作失敗）
  - 於「建立後系統依起迄日產生對應數量的旅程日期」Rule 下新增 Example（起迄同一天產生 1 筆旅程日期）
  - `erm.dbml` 的 `trips` Note 補充跨屬性不變條件：`end_date >= start_date`
