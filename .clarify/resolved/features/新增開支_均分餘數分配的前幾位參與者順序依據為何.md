# 釐清問題

均分餘數「依序分配給前幾位參與者」中,參與者的順序依據為何?

# 定位

Feature:「新增開支」的 Rule「均分時金額平均分配,餘數依序分配給前幾位參與者」。Example 中 "Alice,Bob,Carol" 的順序直接作為分配順序,但未定義該順序從何而來(選取順序?加入旅程順序?排序規則?)。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 使用者在表單中勾選參與者的順序(所見即所得) |
| B | 參與者加入旅程的先後順序(trip_members 建立順序,結果可重現) |
| C | 付款人優先,其餘依加入旅程順序 |
| D | 依姓名字典序排序 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- 均分演算法的輸入定義:分攤函式需要一個確定性的參與者排序,否則同一輸入可能產生不同明細
- `src/lib/settlement` 相關純函式的單元測試(斷言哪位參與者拿到餘數)
- 「編輯開支」重新計算分攤時能否重現同樣結果
- 開支表單參與者選取元件是否需保留勾選順序狀態

# 優先級

High
- 「依序」未定義即無法寫出確定性的分攤函式與可重現的測試,阻礙核心功能定義

---
# 解決記錄

- **回答**:B - 參與者加入旅程的先後順序(trip_members 建立順序,結果可重現)
- **更新的規格檔**:spec/features/新增開支.feature、spec/erm.dbml
- **變更內容**:均分 Rule 改寫為「尾差以 0.01 依參與者加入旅程的先後順序分配給前幾位參與者」;兩個均分 Example 的 Given 改為「旅程的團員依加入順序為」;expenses Note 補上對應跨屬性不變條件;trip_members Note 註明加入順序需可回溯
