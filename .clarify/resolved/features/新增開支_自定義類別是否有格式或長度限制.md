# 釐清問題

類別選擇「自定義字串」時,該字串是否有格式或長度限制?

# 定位

Feature:「新增開支」的 Rule「類別為必填」,Example 僅涵蓋空字串。
ERM:`expenses.category` note「住宿 / 吃喝 / 購物 / 其他 / 自定義字串,必填」,未定義自定義字串的邊界(僅空白字元?長度上限?)。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | trim 後不可為空字串,無長度限制(比照名稱類欄位慣例) |
| B | trim 後不可為空字串,且有長度上限(如 20 字) |
| C | 任意非空字串皆可,不做 trim 檢查 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- `expenses.category` 的 ERM note 補充
- 類別選取元件(預設選項 + 自訂輸入)的驗證規則
- 「類別為必填」規則是否需補充自定義字串的 Example

# 優先級

Low
- 細節調整;可與品項名稱的 trim 釐清([[新增開支_品項名稱僅由空白字元組成時是否視為未填寫]])一併決定

- **回答**:Short - 自定義類別有名稱與圖示兩欄位;名稱必填且 trim 後不可為空(追問確認),圖示選填;儲存與圖示規則比照交通工具(mode + icon)模式(追問確認)
- **更新的規格檔**:spec/erm.dbml、spec/features/新增開支.feature
- **變更內容**:`expenses.category` note 改寫為「類別名稱,必填,trim 後不可為空字串;前端以選單呈現四個預設選項並允許自定義」;新增 `expenses.category_icon` 欄位(選填,僅適用自定義類別);expenses Note 新增跨屬性不變條件(預設類別時 category_icon 必為空,改回預設時自動清除);「類別為必填」Rule 新增空白字元 Example
