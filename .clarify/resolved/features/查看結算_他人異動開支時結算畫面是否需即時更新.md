# 釐清問題

使用者停留在結算畫面時,其他團員新增/編輯/刪除開支,結算結果(餘額與結清清單)是否需即時更新?

# 定位

Feature:`查看結算.feature` 整體時間邊界。CLAUDE.md 之 MVP 清單第 3 項「即時同步」僅明確涵蓋「行程」;第 4 項分帳未提及即時性。技術上既有 TanStack Query × Supabase Realtime 整合點可沿用(監聽 expenses / expense_splits 變更後 invalidate 重算)。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不需即時——進入頁面時計算,重新整理才更新;即時同步僅限行程(照 MVP 清單字面範圍) |
| B | 需即時——沿用既有 Realtime → invalidate Query 整合,開支異動即重算(結算為純函式,成本低) |
| C | 不即時,但提供手動「重新整理」動作 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- 結算頁的 Client Component 是否訂閱 expenses / expense_splits 的 Realtime 事件
- 若選 B,`查看結算.feature` 需補「他人異動後結算即時反映」的 Example
- 不影響 `src/lib/settlement` 純函式本身

# 優先級

Low
- 屬 UX / 架構延伸,預設可依 MVP 清單字面範圍(僅行程即時)先行,不阻礙規則定義

---
# 解決記錄

- **回答**:B - 需即時(沿用既有 TanStack Query × Supabase Realtime 整合:監聽 expenses / expense_splits 變更後 invalidate 重算;結算為純函式,成本低,並多一個技術亮點展示點)
- **更新的規格檔**:spec/features/查看結算.feature
- **變更內容**:新增 Rule「其他團員異動開支後,正在查看結算的使用者所見結算結果即時更新」與 Example「他人新增開支後餘額與結清清單即時反映」(B 正在查看結算,A 新增均分開支 1000,B 所見淨額與結清清單即時更新)。
