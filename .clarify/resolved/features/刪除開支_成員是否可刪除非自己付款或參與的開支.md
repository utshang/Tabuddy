# 釐清問題

任一旅程成員是否可刪除任何開支（包含自己既非付款人、也非分攤參與者的開支），或刪除權限有所限制？

# 定位

Feature：`刪除開支` 的 Rule「成員可以刪除開支」與其 Example「成員成功刪除開支」。目前 Given 僅陳述 Alice 是旅程成員，未說明她與開支「住宿」的關係（付款人？參與者？無關成員？），規則字面上允許任一成員刪除任何開支，但未有 Example 明確驗證「無關成員」這個類別邊界。可對照：`trip_members` 對「刪除旅程」有 owner 限制，但開支操作未定義角色限制；市面分帳工具（如 Splitwise）對此有不同做法。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 任一成員皆可刪除任何開支（規則維持現狀，補一個「非付款人亦非參與者的成員成功刪除」Example 明確化） |
| B | 僅付款人可刪除該筆開支 |
| C | 僅付款人或 owner 可刪除該筆開支 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

影響 `刪除開支.feature` 的 Rule「成員可以刪除開支」是否需改寫或新增前置條件 Rule 與失敗 Example；若選 B/C，亦影響 RLS policy 設計（delete policy 需比對 payer_id 或 role）與前端刪除按鈕的顯示條件。與已解決項目「刪除旅程：僅 owner 可刪除」的角色權限脈絡相關。

# 優先級

Medium
- 原因：規則字面已有預設解讀（任一成員可刪），但若答案為限制刪除，將實質改變 RLS 設計與 UI 行為；屬類別邊界覆蓋缺口。

# 解決記錄

- **回答**：A - 任一成員皆可刪除任何開支（規則維持現狀，補 Example 明確化）
- **更新的規格檔**：spec/features/刪除開支.feature
- **變更內容**：
  - Rule 改寫為「成員可以刪除開支，不限付款人或分攤參與者」以明確化權限範圍
  - 新增 Example「非付款人亦非參與者的成員成功刪除開支」（Carol 為團員但非付款人 Alice 亦非參與者 Alice,Bob，仍成功刪除）
