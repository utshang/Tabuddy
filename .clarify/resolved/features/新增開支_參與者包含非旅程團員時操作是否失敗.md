# 釐清問題

分攤參與者名單中包含非旅程團員時,操作是否失敗?

# 定位

Feature:「新增開支」的 Rule「參與分攤的團員至少一人」措辭隱含參與者應為團員,但沒有「參與者必須皆為旅程團員」的明文規則與 Example(付款人有對應規則「必須是旅程團員」,參與者沒有)。
ERM:`expense_splits.user_id` 僅註明「參與分攤的團員」,外鍵指向 `users` 而非 `trip_members`,約束未落到模型層。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 操作失敗:任一參與者非團員即整筆拒絕(與付款人規則對稱) |
| B | 自動剔除非團員後,以剩餘參與者繼續建立 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- 「新增開支」是否新增一條規則與 Example
- server 端驗證與 RLS policy 設計(expense_splits 寫入時檢查 trip_members)
- 併發情境:成員被移除的同時被加入分攤名單的行為基準

# 優先級

Medium
- 正常 UI 流程只會列出團員,但 server 端驗證行為需明文定義

---
# 解決記錄

- **回答**:A - 操作失敗:任一參與者非團員即整筆拒絕(與付款人規則對稱)
- **更新的規格檔**:spec/features/新增開支.feature、spec/erm.dbml
- **變更內容**:「新增開支」新增 Rule「參與者必須皆為旅程團員」與失敗 Example;`expense_splits.user_id` note 補上「必須為該旅程的團員;任一參與者非團員時整筆開支不建立」
