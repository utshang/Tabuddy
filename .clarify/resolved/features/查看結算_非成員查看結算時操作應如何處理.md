# 釐清問題

非旅程成員的使用者查看某旅程的結算時,操作應如何處理?

# 定位

Feature:`查看結算.feature` 全部 Rule。本 feature 目前缺少「使用者必須是旅程成員」的前置條件 Rule,而其他所有功能(新增開支、刪除開支、新增行程等)均有此規則與對應的「操作失敗」Example。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 操作失敗——與全案其他功能一致,非成員不可查看結算(RLS 亦以 trip_members 把關) |
| B | 可查看——結算為唯讀資訊,不設成員限制 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- `查看結算.feature`:需新增前置條件 Rule 與「非成員查看結算操作失敗」Example
- RLS policy 設計:expenses / expense_splits 的讀取權限(CLAUDE.md 安全模型以 trip_members 為核心,選 A 可直接沿用)
- 相關已解決項目:`resolved/features/新增開支_參與者包含非旅程團員時操作是否失敗.md`(成員資格驗證慣例)
