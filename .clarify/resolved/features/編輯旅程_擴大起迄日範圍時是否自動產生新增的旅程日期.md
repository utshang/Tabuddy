# 釐清問題

編輯旅程將起迄日範圍擴大（提早起日或延後迄日）時，系統是否應自動產生新增日期範圍對應的旅程日期（days）？

# 定位

ERM：`days` 目前 Note 僅說明「依旅程起迄日自動產生，旅程有幾天就有幾筆」，此規則明確對應建立旅程當下的行為，但未定義旅程建立後、範圍擴大時是否比照辦理。
Feature：編輯旅程 — 目前僅涵蓋編輯名稱，未有任何 Rule 或 Example 涉及起迄日擴大後的旅程日期產生邏輯，與 [[編輯旅程_縮減起迄日範圍時已存在的旅程日期與行程如何處理]] 屬同一組「起迄日編輯後 days 重新計算」的決策，建議一併處理。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 是，比照建立旅程邏輯，自動產生新增範圍對應的旅程日期，`order` 接續現有排序 |
| B | 否，擴大範圍不會自動產生旅程日期，需由使用者於行程頁另行新增日期 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/erm.dbml`：`days` Note 需補充「編輯旅程擴大範圍」情境下的產生規則
- `spec/features/編輯旅程.feature`：需新增 Rule + Example（擴大起迄日後新增對應旅程日期）
- 新增行程、行程時間軸 feature 的資料一致性

# 優先級

High
- High：與縮減範圍的決策同屬編輯起迄日功能的核心前提，缺此決策無法完整定義編輯旅程的資料變更行為

---
# 解決記錄

- **回答**：A - 是，比照建立旅程邏輯，自動產生新增範圍對應的旅程日期
- **更新的規格檔**：`spec/features/編輯旅程.feature`、`spec/erm.dbml`
- **變更內容**：
  - `編輯旅程.feature` 新增 Rule「擴大起迄日範圍時系統自動產生新增範圍內對應的旅程日期」，含「延後迄日新增旅程日期」與「提早起日新增旅程日期」兩個 Example
  - `erm.dbml` 的 `days` Note 補充擴大範圍時的產生規則，並說明 `order` 依日期順序重新編號以維持與 `date` 的順序一致
