# 釐清問題

Rule「套用結清清單後所有團員淨額為 0」中的「套用結清清單」是使用者可執行的系統操作(標記已結清並持久化),還是僅為描述演算法正確性的驗證性規則?

# 定位

Feature:`查看結算.feature` Rule「套用結清清單後所有團員淨額為 0」及其 Example「執行結清清單後各人淨額歸零」。該 Example 的 When 步驟「套用結清清單」無操作主詞(其他 feature 的 When 均為「使用者…」),Given 直接給定結清清單與淨額而非由開支推導,讀起來像數學不變條件而非交互功能。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅為驗證性規則——描述演算法不變條件(結清清單金額和 = 各人淨額),無使用者操作、無持久化,對應純函式的屬性測試 |
| B | 為使用者操作——可標記「已結清」並寫入資料庫,需新增 settlements 實體與對應功能規格 |
| C | MVP 為驗證性規則,標記結清列為 stretch goal 後補 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- 資料建模:選 B 需在 `spec/erm.dbml` 新增結算/轉帳記錄實體;選 A/C 則 ERM 不變(結算為即時計算的衍生結果,無持久化)
- 功能邊界:選 B 需拆出獨立的「標記結清」feature(含權限、部分結清、結清後新增開支等連鎖規則),超出 CLAUDE.md 之 MVP 清單
- 測試設計:選 A 對應 `src/lib/settlement` 純函式的不變條件測試
- 相關已解決項目:`resolved/features/刪除旅程_存在未結清開支時owner是否仍可刪除旅程.md`(既有決議:結算為即時計算、無「已結清」狀態——與選項 A/C 相容,若選 B 需重新檢視該決議)

# 解決記錄

- **回答**:A - 僅為驗證性規則(演算法不變條件,無使用者操作、無持久化)
- **更新的規格檔**:spec/features/查看結算.feature
- **變更內容**:Rule 4 標題補註「(演算法不變條件,非使用者操作)」;Example 改為由開支推導(Given 團員與開支、When 使用者查看結算、Then 套用結清清單後各團員淨額為 0),與其他 Rule 句型一致;Feature 描述補「結算結果為即時計算的衍生資料,不持久化;無已結清狀態與標記結清操作」。ERM 不新增實體。
