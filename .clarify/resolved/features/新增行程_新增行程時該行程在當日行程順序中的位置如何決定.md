# 釐清問題

新增行程時，該行程在當日行程順序（order）中的位置如何決定？

# 定位

ERM：`activities.order`（"在當日行程中的排序，用於時間軸計算"，not null，但未定義新增時的賦值規則）。
Feature：新增行程 — 三條 Rule（成員驗證、名稱必填、成功新增）與其 Example 皆未提及 order 欄位如何賦值，Given/When/Then 中完全未出現 order。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 新行程固定加入該日行程順序的最後（order = 現有行程數量 + 1） |
| B | 使用者可於新增時自訂插入位置（例如指定要插在第幾個） |
| C | 新行程一律加入最前面（order = 1，其餘行程 order 依序 +1） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/新增行程.feature`：需新增對應 Rule 與 Example
- `spec/erm.dbml`：`activities.order` 說明需補充賦值規則
- 與「調整行程順序」「行程時間軸」兩個 feature 的資料一致性（後者依賴 order 計算時間軸）

# 優先級

High
- High：阻礙新增行程功能的完整後置條件定義，且直接影響其他依賴 order 欄位的 feature 能否正確運作

---
# 解決記錄

- **回答**：A - 新行程固定加入該日行程順序的最後（order = 現有行程數量 + 1）
- **更新的規格檔**：`spec/features/新增行程.feature`、`spec/erm.dbml`
- **變更內容**：
  - `新增行程.feature` 新增 Rule「新增的行程固定加入當天行程順序的最後」，含「當天尚無行程」與「當天已有行程」兩個 Example
  - `erm.dbml` 的 `activities.order` note 補充新增時的賦值規則
