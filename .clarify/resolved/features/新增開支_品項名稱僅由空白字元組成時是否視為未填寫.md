# 釐清問題

品項名稱僅由空白字元組成(如 "   ")時,是否視為未填寫而操作失敗?

# 定位

Feature:「新增開支」的 Rule「品項名稱為必填」,現有 Example 僅涵蓋空字串 ""。
ERM:`expenses.name` note 僅寫「必填」,未如 `trips.name`、`activities.name` 註明「trim 後不可為空字串」。
相關已解決項目:「建立旅程_旅程名稱僅由空白字元組成時是否視為未填寫」「新增行程_行程名稱僅由空白字元組成時是否視為未填寫」「編輯交通時間_交通工具名稱僅由空白字元組成時是否視為未填寫」——皆採 trim 後不可為空,但均針對其他實體,尚未涵蓋開支。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | trim 後為空即視為未填寫,操作失敗(與旅程/行程/交通工具名稱慣例一致) |
| B | 只要非空字串即可,空白字元視為有效名稱 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- `expenses.name` 的 ERM note 是否補上 trim 規則
- 「品項名稱為必填」規則是否新增空白字元 Example
- 開支表單的 Zod 驗證 schema

# 優先級

Medium
- 影響邊界條件與測試完整性;既有慣例強烈暗示選 A,但需明文化以維持一致性

# 解決記錄

- **回答**:A - trim 後為空即視為未填寫,操作失敗(與旅程/行程/交通工具名稱慣例一致)
- **更新的規格檔**:spec/erm.dbml、spec/features/新增開支.feature
- **變更內容**:`expenses.name` note 補上「trim 後不可為空字串」;「品項名稱為必填」Rule 新增空白字元 Example
