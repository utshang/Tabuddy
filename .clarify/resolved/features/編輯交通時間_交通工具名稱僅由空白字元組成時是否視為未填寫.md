# 釐清問題

編輯交通時間時，若交通工具名稱僅由空白字元組成（例如 " "），是否視為未填寫而操作失敗？

# 定位

Feature：編輯交通時間，Rule「編輯後的交通工具為必填」——目前 Example 僅涵蓋空字串 `""`，未涵蓋純空白字串。
ERM：`transports.mode` note 僅載明「必填」，未如 `trips.name`、`activities.name` 明確標註「trim 後不可為空字串」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 視為未填寫，trim 後為空即操作失敗（與旅程名稱、行程名稱的既有決議一致） |
| B | 只要非空字串即為合法輸入，不做 trim 檢查 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

決定「編輯後的交通工具為必填」Rule 是否需補上純空白字串的失敗 Example；若決議為 A，需同步更新 `spec/erm.dbml` 中 `transports.mode` 的 note（補上 trim 規則），且 `新增交通時間.feature` 的「交通工具名稱為必填」Rule 亦應一致適用。相關已解決項目：[[建立旅程_旅程名稱僅由空白字元組成時是否視為未填寫]]、[[新增行程_行程名稱僅由空白字元組成時是否視為未填寫]]（皆決議為 trim 後不可為空）。

# 優先級

Medium
- 屬於特殊值邊界條件，答案決定驗證邏輯是否包含 trim 與對應測試案例；有既有決議可參照，不確定性低但需明確定案以維持一致性。

# 解決記錄

- **回答**：A - 視為未填寫，trim 後為空即操作失敗（與旅程名稱、行程名稱的既有決議一致）
- **更新的規格檔**：spec/erm.dbml, spec/features/編輯交通時間.feature, spec/features/新增交通時間.feature
- **變更內容**：`transports.mode` note 補上「trim 後不可為空字串」；編輯交通時間 Rule「編輯後的交通工具為必填」與新增交通時間 Rule「交通工具名稱為必填」各補上一個僅含空白字元（" "）操作失敗的 Example
