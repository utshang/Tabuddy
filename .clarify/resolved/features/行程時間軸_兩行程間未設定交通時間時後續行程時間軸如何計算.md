# 釐清問題

兩個相鄰行程之間未設定交通時間時（`transports` 為選填，行程後可以沒有交通段），後續行程的時間軸應如何計算？

# 定位

Feature：行程時間軸 Rule「後續行程的時間軸 = 前一行程時間軸 + 前一行程停留時間 + 兩行程間的交通時間」— 唯一的 Example 中兩行程間皆已設定交通時間，未涵蓋「前一行程之後沒有交通時間」的情境。
ERM：`transports.after_activity_id`（activities 1:1 transports，每個行程後「可選擇性」接一段交通時間）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 視為交通時間 0 分鐘，照常累計（後續時間軸 = 前一時間軸 + 前一停留時間） |
| B | 自該行程起不顯示時間軸（缺交通資訊即中斷計算） |
| C | 不允許查看：該日時間軸整體不顯示，提示補齊交通時間 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/行程時間軸.feature`：需新增 Rule（或於既有 Rule 補充定義）+ Example；亦建議補一個「三個以上行程、部分有交通部分沒有」的混合累計 Example
- `src/lib` 時間軸計算純函式的實作與單元測試設計
- 若選 B 或 C，UI 的 empty / 提示狀態設計也會受影響

# 優先級

High
- High：交通時間為選填是常態情境（使用者通常先排行程、後補交通），此規則未定義會阻礙時間軸核心計算的完整實作

---
# 解決記錄

- **回答**：A - 視為交通時間 0 分鐘，照常累計（後續時間軸 = 前一時間軸 + 前一停留時間）
- **更新的規格檔**：spec/features/行程時間軸.feature、spec/erm.dbml
- **變更內容**：於 `行程時間軸.feature` 新增 Rule「兩行程間未設定交通時間時，交通時間以 0 分鐘計算」及 2 個 Example（純無交通、部分有交通的混合累計）；於 `erm.dbml` 的 `transports` Note 補充「兩行程間未設定交通時間時，時間軸計算視為 0 分鐘」
