# 釐清問題

開支的分攤方式為 custom（自訂金額）時，若編輯僅修改開支金額而未同時提供新的分攤明細，系統應如何處理（原明細總和將不再等於新金額）？

# 定位

- Feature：`編輯開支.feature` Rule「編輯後採自訂金額時各參與者分攤金額之和必須等於開支金額」——現有 Example 僅涵蓋「同時提供分攤但總和不符」的失敗案例，未定義「僅改金額、未重新指定分攤」的行為
- ERM：`expenses` 跨屬性不變條件「所有關聯 expense_splits 的 amount 總和 = expenses.amount」
- 對照：split_type 為 even 時已有明確行為（金額改為 1000 的 Example 顯示自動重算）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 操作失敗：custom 開支修改金額時必須同時提供總和相符的新分攤明細（編輯表單一次提交全部欄位，總和不符即失敗） |
| B | 依原分攤比例自動重算各參與者金額（含尾差處理規則） |
| C | 自動切換為均分（split_type 改為 even 並重算） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- `編輯開支.feature` 需補上對應 Rule 或 Example
- 編輯開支表單的驗證策略（Zod schema）與 UX 行為（是否強制展開分攤區塊）
- 若選 B，需另定比例重算的尾差規則，影響測試案例設計

# 優先級

High
- 未定義時無法實作編輯驗證邏輯；不變條件可能被破壞，直接影響結算正確性

---
# 解決記錄

- **回答**：A - 操作失敗：custom 開支修改金額時必須同時提供總和相符的新分攤明細
- **更新的規格檔**：spec/features/編輯開支.feature
- **變更內容**：在 Rule「編輯後採自訂金額時各參與者分攤金額之和必須等於開支金額」下新增 Example「自訂金額開支僅修改金額而未重新指定分攤時操作失敗」
