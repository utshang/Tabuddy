# 釐清問題

時間軸累計超過午夜（24:00）時應如何呈現？例如 start_time "22:00"、停留 90 分鐘、交通 1 小時後，下一行程的時間軸落在隔日凌晨。

# 定位

Feature：行程時間軸 Rule「後續行程的時間軸 = 前一行程時間軸 + 前一行程停留時間 + 兩行程間的交通時間」— 累計結果無上限（`activities.duration_minutes` 必須 > 0 但無上限、`transports.hours` >= 0 無上限），現有 Example 皆未觸及 24:00 邊界。
ERM：`days.start_time`（HH:MM）、`activities.duration_minutes`、`transports.hours` / `minutes`。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以 24 小時制取模顯示（例如 "01:30"），不特別標示跨日 |
| B | 以 24 小時制取模顯示並加註跨日標示（例如 "01:30 +1"） |
| C | 直接顯示累計時數（例如 "25:30"） |
| D | 超過 23:59 的行程顯示為 "23:59"（封頂） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/行程時間軸.feature`：需新增邊界 Rule + Example（剛好 24:00、超過 24:00）
- 時間軸計算純函式的輸出格式與單元測試
- 時間軸 UI 呈現（是否需要跨日視覺標示）

# 優先級

Medium
- Medium：屬時間邊界條件，不阻礙核心公式定義，但影響計算函式的輸出契約與測試完整性

---
# 解決記錄

- **回答**：Short - 以 24 小時制取模顯示（例如 "01:30"），並於時間下方標示所屬日期（隔天日期，例如 "7/24"）
- **更新的規格檔**：spec/features/行程時間軸.feature
- **變更內容**：新增 Rule「時間軸跨過午夜時，以 24 小時制循環顯示並標示為隔天日期」及 Example（start_time "22:00" 累計至 "01:30"，時間軸日期為隔天 "2025-06-02"）
