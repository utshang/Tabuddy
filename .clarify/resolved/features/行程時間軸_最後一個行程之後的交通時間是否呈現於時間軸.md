# 釐清問題

當日最後一個行程之後若存在交通時間（例如回飯店的交通），時間軸應如何處理該交通段？

# 定位

Feature：行程時間軸 — 現有 Rule 僅定義「行程」的時間軸，交通時間只作為兩行程間的加項；但依「新增交通時間」的 Example，在當日唯一（即最後一個）行程之後新增交通時間是合法操作，該交通段之後沒有下一個行程可承接其時間。
ERM：`transports.after_activity_id`（任一行程之後皆可接一段交通時間，包含當日最後一個行程）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 照常顯示該交通段（時間軸僅計算至最後行程，交通段僅呈現不影響計算） |
| B | 時間軸不顯示最後行程之後的交通段 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/行程時間軸.feature`：若選 A，需明確定義交通段在時間軸中的呈現（是否也標時間）；若選 B，需一條排除規則
- 時間軸 UI 的行程／交通段渲染邏輯

# 優先級

Low
- Low：不影響行程時間軸的核心計算公式，屬呈現層細節

# 解決記錄

- **回答**：A - 照常顯示該交通段（時間軸僅計算至最後行程，交通段僅呈現不影響計算）
- **更新的規格檔**：spec/features/行程時間軸.feature、spec/erm.dbml
- **變更內容**：於 `行程時間軸.feature` 新增 Rule「最後一個行程之後的交通時間照常顯示，不影響時間軸計算」及 Example；於 `erm.dbml` 的 `transports` Note 補充對應說明
