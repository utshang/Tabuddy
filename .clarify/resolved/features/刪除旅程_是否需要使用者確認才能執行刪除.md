# 釐清問題

執行刪除旅程時，是否需要使用者二次確認才會實際刪除（防止誤刪）？

# 定位

Feature：`刪除旅程` 的「只有建立者可以刪除旅程」規則與其 Example「owner 成功刪除旅程」，目前 When 步驟直接執行刪除、Then 直接驗證旅程不存在，未經過確認步驟。可對照 `編輯旅程.feature` 中「縮減起迄日範圍且範圍外的旅程日期包含行程時，系統須經使用者確認才會刪除」已有前例。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 需要確認：使用者執行刪除後，需再「確認刪除」才真正刪除旅程；取消確認則不執行 |
| B | 不需要確認：使用者執行刪除即立即生效（由前端 UI 自行決定是否加確認彈窗，不寫入規格）|
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

影響 `刪除旅程.feature` 是否需新增「使用者確認刪除」與「使用者取消刪除」相關 Rule 與 Example，並決定前端刪除按鈕的互動流程設計。

# 優先級

Medium
- 原因：不影響核心資料模型，但直接決定功能規則的完整性與測試案例設計，且刪除旅程為不可逆操作，遺漏此規則會導致誤刪風險未被規格涵蓋。

---
# 解決記錄

- **回答**：A - 需要確認：使用者執行刪除後，需再「確認刪除」才真正刪除旅程；取消確認則不執行
- **更新的規格檔**：spec/features/刪除旅程.feature
- **變更內容**：
  - 「owner 成功刪除旅程」與「刪除旅程後旅程日期、行程與開支皆不存在」兩個 Example 的 When 步驟新增「使用者確認刪除旅程」步驟
  - 新增 Rule「刪除旅程需經使用者確認才會執行」，含 Example「使用者取消確認時旅程仍存在」
