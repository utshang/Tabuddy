# 釐清問題

刪除行程是否需要使用者確認才能執行？

# 定位

Feature：`刪除行程.feature`（Rule: 成員可以刪除行程 / Example: 成員成功刪除行程）。目前 Example 為使用者執行刪除後即直接視為成功，未經確認步驟。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 需要確認：比照 `刪除旅程.feature`（Rule: 刪除旅程需經使用者確認才會執行）的模式，新增確認/取消確認步驟與對應 Example |
| B | 不需要確認：行程刪除為低風險、高頻率操作，直接執行不需二次確認 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

影響 `刪除行程.feature` 是否需新增「使用者確認刪除」與「使用者取消確認」兩條 Rule 及對應 Example（比照 `刪除旅程.feature` 的既有模式），以及前端刪除行程 UI 是否需彈出確認對話框。

# 優先級

Medium
- 屬於 UX 行為與測試案例完整性的決策點，不影響核心資料模型，但會影響 Example 覆蓋度與前端實作。

---
# 解決記錄

- **回答**：A - 需要確認：比照 `刪除旅程.feature` 的模式，新增確認/取消確認步驟與對應 Example
- **更新的規格檔**：spec/features/刪除行程.feature
- **變更內容**：新增「刪除行程需經使用者確認才會執行」規則與「使用者取消確認時行程仍存在」Example；並在既有 3 個成功刪除的 Example（成員成功刪除行程、順序重新編號、交通時間一併刪除）中補上「使用者確認刪除行程」步驟
