# 釐清問題

若某個旅程日期尚未設定開始時間（`days.start_time` 為選填，可能為空），該日第一個行程的時間軸應如何呈現或計算？

# 定位

ERM：`days.start_time`（選填）。
Feature：行程時間軸 Rule「當日第一個行程的時間軸等於該日的開始時間」— 目前所有 Example 的 Given 皆已先設定 start_time，未涵蓋 start_time 未設定時的情境。
Feature：設定當日開始時間 — start_time 為選填欄位，代表系統必須存在「尚未設定」的可能狀態，此狀態會直接影響行程時間軸功能的核心計算規則。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 未設定時視為預設值 "00:00" 計算時間軸 |
| B | 未設定時不顯示時間軸（該日行程無時間軸資訊） |
| C | 未設定開始時間的日期，不允許新增行程（需先設定開始時間） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- `spec/features/行程時間軸.feature`：可能需新增 Rule + Example
- `spec/features/新增行程.feature`：若選項 C，需新增對應前置條件
- `spec/erm.dbml`：`days.start_time` note 可能需調整為必填或補充預設值說明

# 優先級

High
- High：時間軸計算為本專案兩大核心亮點功能之一（見 CLAUDE.md「即時協作行程編輯」與「時間軸計算」），此情境未定義會阻礙核心功能的完整實作

# 解決記錄

- **回答**：Short - 沒設定時，當作 "08:00" 來計算時間軸
- **更新的規格檔**：spec/features/行程時間軸.feature、spec/erm.dbml
- **變更內容**：於 `行程時間軸.feature` 新增 Rule「當日未設定開始時間時，時間軸以 "08:00" 計算」及對應 Example；於 `erm.dbml` 的 `days.start_time` note 補充「若未設定，時間軸計算時視為 "08:00"」
