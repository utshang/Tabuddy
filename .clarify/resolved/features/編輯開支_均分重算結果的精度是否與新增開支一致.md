# 釐清問題

編輯開支後採均分時，重算結果的精度是否與新增開支一致（平均分配至小數第二位，尾差以 0.01 分配）？目前 Example「金額改為 1000 且由 3 人均分 → 334、333、333」採整數分配，與 ERM 不變條件及新增開支的「1000 元由 3 人均分 → 333.34、333.33、333.33」矛盾。

# 定位

- Feature：`編輯開支.feature` Rule「編輯後採均分時金額平均分配，餘數依序分配給前幾位參與者」及其 Example（334/333/333）
- ERM：`expenses` 跨屬性不變條件「split_type 為 even 時，金額平均分配至小數第二位，尾差以 0.01 依參與者加入旅程的先後順序分配給前幾位參與者」
- 相關已解決項目：`resolved/data/expenses_金額是否僅允許整數.md`、`resolved/features/新增開支_均分餘數分配的前幾位參與者順序依據為何.md`

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 與新增開支一致：平均分配至小數第二位，尾差 0.01 依加入順序分配（修正 Example 為 333.34/333.33/333.33，Rule 措辭比照新增開支） |
| B | 編輯採整數分配（新增與編輯精度不一致，需另立規則說明差異與理由） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- `編輯開支.feature` 的均分 Rule 與 Example
- 均分重算邏輯的實作（新增與編輯應共用同一純函式）
- settlement 演算法的輸入資料精度假設
- 若選 B，`erm.dbml` 的不變條件需改寫為區分新增／編輯

# 優先級

High
- 規格自相矛盾，直接阻礙均分重算邏輯的實作與測試設計

# 解決記錄

- **回答**：A - 與新增開支一致：平均分配至小數第二位，尾差 0.01 依加入順序分配
- **更新的規格檔**：spec/features/編輯開支.feature
- **變更內容**：Rule 措辭改為「編輯後採均分時金額平均分配至小數第二位，尾差以 0.01 依參與者加入旅程的先後順序分配給前幾位參與者」；Example 修正為 333.34/333.33/333.33，Given 句型統一為「的團員依加入順序為」（與新增開支一致）；ERM 不變條件原已如此定義，無需變更
