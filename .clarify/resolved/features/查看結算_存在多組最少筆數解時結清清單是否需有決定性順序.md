# 釐清問題

同一組淨額可能存在多組轉帳筆數相同的最優解(誰轉給誰、清單排序不同),結清清單的輸出是否需具決定性?若需要,配對與排序的 tie-break 規則為何?

# 定位

Feature:`查看結算.feature` Rule「系統以最少轉帳筆數計算結清清單」的 Example「三人情境結算為 2 筆轉帳」——Then 步驟以精確表格(含列順序)斷言結清清單,隱含輸出必須決定性,但規格未定義配對與排序規則。

例:淨額 A:+100, B:+100, C:−100, D:−100 時,「C→A, D→B」與「C→B, D→A」筆數相同,皆為合法最優解。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 需決定性:金額由大到小排序,同額時依團員加入旅程的先後順序 tie-break(與均分尾差慣例一致) |
| B | 需決定性:債權人與債務人各依加入旅程順序配對 |
| C | 不要求決定性:測試僅驗證筆數最少與套用後淨額歸零,不斷言精確清單 |
| Short | 提供其他簡短答案(<=5 字) |

# 影響範圍

- 所有以精確表格斷言結清清單的 Example 是否可穩定通過
- `src/lib/settlement` 的排序/配對實作與單元測試寫法(精確斷言 vs. 屬性斷言)
- 相關已解決項目:`resolved/features/新增開支_均分餘數分配的前幾位參與者順序依據為何.md`(加入順序作為 tie-break 的既有慣例,選項 A/B 沿用)
- 依賴關係:需先釐清〈最少轉帳筆數是否要求絕對最少或允許貪婪演算法結果〉,演算法選擇決定解空間

# 解決記錄

- **回答**:A - 需決定性:淨額相同時依團員加入旅程的先後順序優先配對;結清清單列順序即 greedy 產生轉帳的順序(與均分尾差的加入順序慣例一致)
- **更新的規格檔**:spec/features/查看結算.feature
- **變更內容**:新增 Rule「淨額相同時依團員加入旅程的先後順序優先配對,結清清單依轉帳產生順序排列」與 Example「兩位團員同額欠款時依加入順序先後轉帳」(A、B 各欠 200 時,依加入順序先 A→C 再 B→C)。
