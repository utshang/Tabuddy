# 釐清問題

付款人(expenses.payer_id)是否必須同時是該筆開支的分攤參與者之一?

# 定位

ERM:`expenses.payer_id` 僅要求「為該旅程的團員之一」,未規範與 `expense_splits` 的關係。
Feature:「新增開支」所有 Example 中付款人恰好都在參與者名單內;「查看結算」的 Example 亦同。付款人代墊但自己不分攤(例如幫其他人買票)的情境未定義。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不必:付款人可不在參與者名單中(代墊情境),淨額 = 付出總額 − 被分攤總額,公式天然支援 |
| B | 必須:付款人一定要在參與者名單內,否則操作失敗 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- 「新增開支」是否需要新增一條規則與對應 Example
- 開支表單的參與者選取驗證邏輯
- 查看結算的淨額計算測試案例(付款人不分攤的情境)

# 優先級

Medium
- 影響邊界條件與測試完整性;淨額公式兩案皆可運作,但驗證行為不同

---
# 解決記錄

- **回答**:A - 不必:付款人可不在參與者名單中(代墊情境)
- **更新的規格檔**:spec/erm.dbml、spec/features/新增開支.feature
- **變更內容**:`expenses.payer_id` note 補上「不要求同時為該筆開支的分攤參與者(可代墊不參與分攤)」;「新增開支」新增 Rule「付款人不必是分攤參與者」與代墊 Example(Alice 付款、Bob/Carol 均分)
