# 釐清問題

開支金額(expenses.amount)與分攤金額(expense_splits.amount)是否僅允許整數(元),或允許小數?

# 定位

ERM:`expenses.amount`(目前型別為 float)、`expense_splits.amount`(float)。
Feature:「新增開支」的 Rule「均分時金額平均分配,餘數依序分配給前幾位參與者」——「餘數」一詞隱含整數除法(Example:1000 / 3 → 334、333、333)。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅允許整數(元),ERM 型別改為 int;「餘數」即整數除法餘數 |
| B | 允許至小數兩位;均分時分配到分為止,尾差依序補給前幾位參與者 |
| C | 允許任意小數,不做尾差調整(總和可能有浮點誤差) |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- `expenses.amount`、`expense_splits.amount` 的資料型別(float 表示金額有精度風險)
- 均分演算法的餘數計算方式與單元測試設計(`src/lib/settlement` 的輸入前提)
- 「自訂金額總和必須等於開支金額」的相等判斷(整數比較 vs 浮點容差)
- 查看結算的淨額與結清清單金額精度
- 開支表單的金額欄位驗證規則

# 優先級

High
- 阻礙資料建模與分攤/結算演算法的核心定義

---
# 解決記錄

- **回答**:B - 允許至小數兩位;均分時分配到 0.01 為止,尾差依序補給前幾位參與者
- **更新的規格檔**:spec/erm.dbml、spec/features/新增開支.feature
- **變更內容**:`expenses.amount` 與 `expense_splits.amount` 的 note 補上「最多至小數第二位」;均分 Rule 改寫為「均分時金額平均分配至小數第二位,尾差以 0.01 依序分配給前幾位參與者」,Example 由 334/333/333 更新為 333.34/333.33/333.33
