# 釐清問題

分攤金額(expense_splits.amount)是否允許為 0?均分結果出現 0 或自訂金額填 0 時應如何處理?

# 定位

ERM:`expense_splits.amount` note 目前定義為「> 0」。
Feature:「新增開支」的 Rule「均分時金額平均分配,餘數依序分配給前幾位參與者」——若金額 2 元由 3 人均分,依規則得 1、1、0,與 ERM 的「> 0」約束衝突;Rule「自訂金額時各參與者分攤金額之和必須等於開支金額」亦未定義某參與者填 0 的行為。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 允許 0:0 為有效分攤明細,ERM 改為 >= 0 |
| B | 不允許:均分結果含 0 或自訂填 0 時操作失敗 |
| C | 不允許但自動處理:自訂填 0 視同未參與(不建立該筆明細);均分含 0 時操作失敗 |
| Short | 提供其他簡短答案(<=5 字)|

# 影響範圍

- `expense_splits.amount` 的邊界約束(> 0 vs >= 0)
- 均分演算法的極小金額邊界案例與單元測試
- 「參與分攤的團員至少一人」規則的實質意涵(0 元參與者算不算參與)
- 查看結算的淨額計算(0 元明細不影響數值,但影響資料筆數與 UI 呈現)

# 優先級

High
- 現行規格存在內部衝突(均分規則 × ERM 約束),阻礙分攤演算法定義

---
# 解決記錄

- **回答**:A - 允許 0:0 為有效分攤明細,ERM 改為 >= 0
- **更新的規格檔**:spec/erm.dbml、spec/features/新增開支.feature
- **變更內容**:`expense_splits.amount` note 改為「>= 0」並註明 0 為有效明細;「新增開支」新增 Rule「分攤金額可為 0」與兩個 Example(自訂填 0 仍建立明細、0.02 元 3 人均分 → 0.01/0.01/0.00)
