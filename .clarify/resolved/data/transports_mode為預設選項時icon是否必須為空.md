# 釐清問題

當 `transports.mode` 為六個預設選項（walking / driving / flight / bus / train / metro）之一時，`icon` 是否必須為空？特別是：原本為自訂交通工具（含圖示）的交通時間，編輯後改回預設選項時，既有 icon 應如何處理？

# 定位

ERM：`transports` 實體的 `mode` 與 `icon` 兩屬性之間的跨屬性不變條件（A4），目前 `icon` note 僅說明「預設六個選項的圖示由前端內建提供，不寫入此欄位」，未定義 mode 從自訂改回預設時的 icon 處理規則。
Feature：編輯交通時間，Rule「成員可以編輯交通時間的交通工具」的邊界情境。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 是，為跨屬性不變條件：mode 為預設選項時 icon 必為空，編輯改回預設選項時系統自動清除 icon（ERM 需補上此不變條件） |
| B | 否，icon 與 mode 無強制關聯，改回預設選項時保留原 icon 值（前端顯示時忽略，仍以內建圖示為準） |
| C | 由前端在選回預設選項時自動清空 icon 送出，後端不驗證此條件 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

若決議為 A，需在 `spec/erm.dbml` 的 `transports` Note 補上跨屬性不變條件，並在 `編輯交通時間.feature` 新增對應 Example（自訂工具＋圖示 → 改回預設選項後 icon 為空）；影響編輯交通時間 API 的驗證／寫入邏輯與時間軸顯示的圖示來源判斷。前置依賴：[[編輯交通時間_是否可編輯交通工具圖示]]（若圖示完全不可編輯，本題僅剩「mode 變更時的自動處理」單一情境）。

# 解決記錄

- **回答**：A - 是，為跨屬性不變條件：mode 為預設選項時 icon 必為空，編輯改回預設選項時系統自動清除 icon
- **更新的規格檔**：spec/erm.dbml, spec/features/編輯交通時間.feature
- **變更內容**：`transports` Note 補上跨屬性不變條件「mode 為六個預設選項之一時 icon 必為空；編輯時將 mode 由自訂名稱改為預設選項，系統自動清除 icon」；Feature 新增 Rule「交通工具改為預設選項時圖示自動清除」與對應 Example（腳踏車🚲 → driving 後 icon 為空）
