# 釐清問題

刪除行程後，同一天其餘行程的 order 是否需要重新編號以維持連續性？

# 定位

ERM：`activities.order` 屬性（跨屬性不變條件）。
已於 `新增行程.feature`（Rule: 新增的行程固定加入當天行程順序的最後）確立「order = 該日既有行程數量 + 1」的計算公式；此公式假設 order 連續無空缺。若刪除行程後不重新編號，該日行程數量會減少但既有行程的 order 值不變（產生空缺），下次新增行程時以「數量 + 1」計算可能與既有 order 值重複。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 刪除後重新編號：同一天其餘行程 order 依序重排為連續整數（1..N），確保「數量 + 1」公式持續成立 |
| B | 不重新編號：允許 order 不連續，改將新增行程的公式由「數量 + 1」改為「該日現有最大 order + 1」 |
| C | 不重新編號且新增公式不變：可能產生 order 重複，需於應用層另加次要排序鍵（如 created_at）處理顯示順序 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

影響 `activities.order` 的維護規則、`新增行程.feature`（Rule: 新增的行程固定加入當天行程順序的最後）之公式是否需修改、`調整行程順序.feature` 的順序更新邏輯，以及 `刪除行程.feature` 是否需新增對應 Rule/Example 說明刪除後的順序狀態。

# 優先級

High
- 影響核心資料完整性：若不釐清，可能導致 order 值重複，造成行程順序顯示錯誤或排序邏輯 bug。

---
# 解決記錄

- **回答**：A - 刪除後重新編號：同一天其餘行程 order 依序重排為連續整數（1..N），確保「數量 + 1」公式持續成立
- **更新的規格檔**：spec/erm.dbml、spec/features/刪除行程.feature
- **變更內容**：在 `activities` Table Note 中新增跨屬性不變條件（刪除後 order 重新編號為連續整數）；在 `刪除行程.feature` 新增「刪除行程後同一天其餘行程順序重新編號」規則與對應 Example
